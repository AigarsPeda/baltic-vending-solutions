# Wrapping design editor

The separate native WordPress pages are `/dizaina-redaktors/` and `/en/design-editor/`. Their `bvs/design-editor` block owns translated tool labels. The intro, headings, wrapping-section button and menus remain native editable WordPress content. Run `scripts/local/setup-design-editor.php` with the local WP wrapper to create missing pages and links; reruns preserve saved editor content. Fresh seeds call it after the starter pages exist.

The editor uses the actual supplied Jāņoga Smart Fridge web model. It is a visual prototype, with three independent editable wrap panels. The screen, payment devices, door, stock and cabinet stay intact. PNG, JPG and WebP images up to 5 MB and 4096px per side are accepted. Images are decoded and reduced to at most 1024px for the working mockup. The front flat template has transparent cut-outs for the display, payment hardware, door and cabinet notch. The same cut-outs apply to exported panel views; the 3D model already separates its hardware geometry. Artwork can fill or fit a panel; a separate logo has width, horizontal/vertical position and rotation controls, pointer dragging and keyboard movement. Double-clicking an individual logo slider restores its panel default: width 22%, rotation 0°, front position 17% horizontal and 6% vertical, or side position 50% horizontal and 35% vertical. Each reset updates the preview, supports undo/redo and saves to the browser draft. Drawing has a tool selector for exact freehand, smoothed freehand, straight lines, rectangles, ellipses and text. Draw / Stop drawing switches between drawing and logo dragging. Shapes can be filled; Shift constrains a rectangle or ellipse to a square or circle. Text is entered in the sidebar and placed with a click, with its own size control. Brush colour/size and bounded undo/redo apply across the design. Undo and redo use labelled 44px arrow-icon buttons beside the desktop preview modes or in the mobile preview header, available in both 3D and 2D views with drawing tools closed. Ctrl/Cmd+Z undoes and Ctrl/Cmd+Shift+Z or Ctrl/Cmd+Y redoes when focus is outside text fields. Logo dragging works when drawing is off. A colour can be copied to all panels. The preview toolbar has an Eraser icon beside undo/redo on desktop and mobile. It toggles item erasing directly on the visible preview without opening drawing tools. The Eraser removes one topmost drawing, shape, text item or logo per click. It tests actual painted pixels, including logo rotation and transparency, with a small selection tolerance. Background artwork, panel colour and machine hardware are preserved. In 3D, choose Erase on machine before clicking; flat 2D editing uses the same tool. Empty clicks leave history intact. Erasing supports undo/redo, updates exports and saves the draft; the selected eraser tool also restores across reloads.

Panel buttons use compact single-line labels: Priekša / Kreisais / Labais or Front / Left / Right. Full panel names remain in accessible labels and tooltips. Desktop places tools beside the 3D machine and flat canvas. Its 2D panels use the original centred width, capped at 200px, with an 18px heading gap shifting the image down by 6px. Proportions and zoom behavior remain intact. In the two-column desktop preview, shared rows align the 3D and 2D zoom controls beneath the taller preview. Mobile defaults to a straight-on front view of the real 3D machine above the tools. This initial view also applies when restoring a saved side-panel draft, while retaining its artwork and panel selection. Explicit side-panel selection still rotates the machine; Reset view returns mobile to the front and desktop to its existing three-quarter view. A corner button switches to the flat 2D panel and back, retaining the same design. The preview spans the viewport width; tool fields retain a 16px inset. Reset view is a 44px icon button in the upper-right corner of the mobile 3D viewport, with a translated accessible name and tooltip. The zoom controls occupy their own row; desktop places the same icon first in the machine preview toolbar, before rotation and drawing modes. The preview sticks within the tools on tall screens and remains in normal flow at heights of 780px or below. The neutral still loads with the model and remains if graphics fail. A failed or timed-out model selects the flat panel on mobile and disables the unavailable 3D switch. Flat editing and PNG export work without 3D. When exporting from 2D view with a ready model, the editor briefly renders the hidden machine for its snapshot and restores the selected view. The model library, fonts and assets are self-hosted; only this page loads the viewer script. One design draft saves automatically to the browser’s IndexedDB database `bvs-design-editor`, store `drafts`, key `smart-fridge`. It is shared by the Latvian and English routes on the same origin. Colours, PNG artwork/logo blobs, fit, placement, strokes, shapes, text, selected tools and flat zoom restore when the browser reopens. Continuous edits debounce by 250ms. Completed changes, uploads, drawing gestures and actions save immediately; pending changes also flush when the page hides. No draft upload, cookie or external service is used. Contact details and undo history are not persisted. The last saved editor tab wins if multiple tabs are used. Start again is a red button at the far right of the desktop actions and last in the full-width mobile stack. After confirmation it clears the design and deletes the saved record; clearing browser site data also removes it. Drafts have no automatic expiry. Blocked or full browser storage shows an explicit failure and leaves editing/export available.

The PNG contains a machine snapshot when available and all three panel mockups. It is a design proposal, not a dimensioned print template. The original supplied print JPEG contains separate cut panels and must not be treated as a single artwork image. Final dimensions and wrap scope need confirmation on the selected machine.

## Drawing and zoom

Exact freehand stores the reported pointer samples, including coalesced pen events, and paints a polyline. Smoothed freehand previews rounded curves; on release, a stroke longer than 30 panel pixels with all points within `8 + brushSize / 2` pixels of its endpoint segment becomes a straight line. Other curves use iterative Ramer–Douglas–Peucker simplification with a 2px tolerance and quadratic midpoint smoothing. Measurements use the actual panel pixel dimensions. This is geometric cleanup, not handwriting or shape recognition.

The viewer has explicit Rotate machine / Draw on machine modes. Drawing disables camera gestures and uses model-viewer's public `materialFromPoint` and `positionAndNormalFromPoint` APIs to map real pointer hits to front/left/right wrap UVs. Hardware and transparent front-template cut-outs reject drawing starts. Freehand crossing a noneditable region breaks the stroke, so it cannot connect across hardware or onto a different panel. Lines, shapes and text use the same normalized panel coordinates as the flat editor; textures, PNG export and automatic enquiry attachment share that paint routine. A gesture creates one undo step, even if a freehand path splits. Cancellation reverts the gesture. History contains at most 20 whole-design snapshots; history itself is not saved. Old version-1 drafts with untyped strokes restore as exact freehand.

Machine zoom supports native viewer gestures in rotate mode and labelled buttons from 75% to 300%. Drawing mode keeps zoom buttons available. Rotate the machine first to expose a panel. Selecting another panel preserves the zoom distance and recentres the target; Reset view returns to the initial angle and distance. Flat zoom runs from 100% to 400% in a scrollable viewport without changing the saved artwork. Move zoomed panel / Continue editing explicitly switches the flat canvas between dragging its viewport and editing; panning works with touch or mouse and arrow keys without changing artwork. Tool changes return to editing. Hit testing uses the displayed canvas bounds, including its scroll offset and zoom. Shapes/text/strokes are bounded to 1000 items and 25000 points per panel, with 5000 samples per stroke. Shapes and text are placed and removed through undo/clear; there is no separate layer rearrangement tool.

## Quote attachment

After the visitor edits a panel, the same-page quote form selects “Include my current editor design” and hides the manual chooser. Submission generates the latest PNG directly in memory, includes it in the request and selects Smart Fridge, without a download or manual upload. An untouched editor does not attach the default design. Visitors can untick the option or remove the design to opt out and use a manual file. Manual file selection also opts out. The editor quote button still prepares a local file and focuses the form; further edits are included when the visitor submits. The visitor must complete and submit the form. Every quote form also has an optional manual image attachment. Failed submissions retain the form and file; successful submissions reset them. On the server, the image must be an actual uploaded PNG/JPEG/WebP, is checked for dimensions and size, decoded, re-encoded as PNG and stripped of metadata. SVG, PDF and arbitrary documents are rejected.

Files are stored outside the web root in `dirname(ABSPATH)/bvs-private-designs`, with directory mode 0700 and file mode 0600. Hosts may define `BVS_PRIVATE_DESIGN_DIR` in `wp-config.php` to another writable directory outside the document root. Storage inside the document root is refused. Each file has a random UUID filename; private enquiry metadata keeps only its descriptor. If storage fails, the enquiry is rolled back and the form reports a failure. No public Media Library attachment or URL is created.

Enquiry administrators download files through a capability and nonce protected `admin-post.php` route. Notification email attaches the normalised file; Local intercepts email. Permanent enquiry deletion removes the file; moving an enquiry to Trash retains it until permanent deletion. Site backups need to include the private directory along with the database. Retention remains subject to the existing business confirmation before launch. The privacy pages describe local drafts and submitted attachments.
